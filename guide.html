🧠 Conceptual Foundation

What Exactly Is an "Agent Harness"?

Before looking at code, let's understand the core problem that creates the need for an agent harness.

💡 The Feynman Analogy: The Brilliant Chef with Amnesia

Imagine a world-class chef who has severe, five-second amnesia. Every time the chef blinks, they forget who they are, where they are, what recipe they were cooking, and whether the stove is on.


An LLM is like that chef: it is a stateless probabilistic next-token predictor. It cannot hold open a terminal session, it cannot run Python in memory across calls, and it cannot see the computer screen.


The Agent Harness is the Sous-Chef standing next to them with a clipboard:
• The sous-chef hands the chef a binder: "Here is who you are, here is the recipe, and here is what you did 3 seconds ago." (Prompt Construction)
• The chef reads it and says: "I need to check if the water is boiling." (Tool Call Action)
• The chef blinks and forgets everything.
• The sous-chef walks to the pot, checks the water, and writes in the binder: "Water is boiling at 100°C." (Observation Execution)
• The sous-chef hands the binder back to the chef. The cycle repeats until dinner is served.

The Stateless API

LLM endpoints (OpenAI/OpenRouter) keep no conversation history between HTTP POST calls. Every turn requires re-sending the whole universe of prior steps.

The ReAct (Reason + Act) Heartbeat

How Agent.run() in base.py drives the alternating cycle of thoughts, actions, and observations.

▶ Animated ReAct Execution Pulse

Live Execution Sequence
src/assignment/agent/base.py • Agent.run() 
def run(self) -> None:
    """Run ReAct steps, always saving the trajectory and stopping Modal."""
    try:
        while not self.finished:
            # 1. Budget check
            if self.steps_taken >= self.step_limit:
                raise StepLimitError(f"Exceeded step limit of {self.step_limit}")

            # 2. Context compaction hook (Part 2)
            self.maybe_compact_context()

            # 3. Query LLM via OpenAI chat completions
            message = self.query_language_model()
            tool_calls = message.get("tool_calls")

            # 4. Branch: Did the model decide to act, or just reflect?
            if tool_calls:
                self.messages.append(message)
                observations = self.execute_tool_calls(tool_calls)
                self.messages.extend(observations)
            else:
                self.messages.append(message)
    finally:
        # Guaranteed cleanup: trajectory written & sandbox safely stopped
        self._save_logs_and_stop_env()
🛡 Security & Execution Architecture

Modal Cloud Sandboxing & SWE-ReX

Why we run commands on a remote cloud cluster instead of your local machine.

💡 The Feynman Analogy: The Hazardous Chemistry Lab

When scientists experiment with toxic viruses or volatile chemicals, they don’t test them on their kitchen table. They build a negative-pressure clean room (glove box) with thick glass and sealed gloves.


An autonomous coding agent generates shell commands dynamically. What if the model runs: rm -rf /, installs a compromised pip package, or spawns a fork bomb?


Modal is the quarantine glove box: Your agent process runs locally on your laptop, but every single bash command, pytest invocation, and chess server runs thousands of miles away inside an ephemeral Linux container on Modal’s cloud. If the agent accidentally blows up the container, your local machine remains 100% pristine.

🔐

Encrypted TLS Tunneling

Inside the Modal container, SWE-ReX starts a remote control daemon. Modal opens an encrypted TLS port tunnel giving your local Environment an HTTPS endpoint to execute commands asynchronously.

♻️

The Pinned Testbed Image

Every evaluation run boots from a deterministic base image built from tasks/chess-terminal-move. verify_source() validates the git commit SHA before building to guarantee 100% test reproducibility.

📋 Two-Level Progressive Disclosure

Agent Skills Protocol

A skill folder (e.g. tasks/code-skills/submit-task/) contains a single SKILL.md file with YAML frontmatter at the top: 

---
name: submit-task
description: When the task is complete, take the required steps to submit the solution. DO NOT submit without invoking this skill.
---

When you have finished, you must submit your changes as a git patch, in three separate steps:
# Step 1: Create the patch file (git diff -- file1 > patch.txt)
# Step 2: Verify patch.txt contains valid diff headers (--- a/ and +++ b/)
# Step 3: Call send_message with your summary

load_skills() parses only the YAML header. The prompt receives only the name and description. The instructions to write patch.txt are intentionally kept hidden! 

<skills>
name: submit-task
description: When the task is complete, take the required steps to submit the solution. DO NOT submit without invoking this skill.
</skills>

When the agent fixes the bug, it calls invoke_skill(name="submit-task"). Only then does the harness return the complete text as a tool observation! 

# Agent action:
Assistant: "I have fixed the chess terminal bug. Let me load the submission instructions."
invoke_skill(name="submit-task")

# Environment Observation returned:
Tool (call_id="call_99"): "Step 1: git diff -- ... > patch.txt\nStep 2: verify...\nStep 3: call send_message"
🧳 Memory Engineering

Context Compaction: The Detective's Notebook

How agents solve 100-turn tasks on SWE-bench without crashing into the LLM context limit.

💡 The Feynman Analogy: The Detective's Pocket Notebook

Imagine a homicide detective investigating a case for three months. If they carried a verbatim transcript of every single phone call, coffee receipt, and witness interrogation everywhere they went, their briefcase would weigh 50 pounds, and finding the culprit’s license plate would take hours.


Instead, good detectives maintain a case summary notebook:
• "Suspect A verified at airport at 4 PM (alibi confirmed)."
• "Fingerprint on gun matches suspect B."
• "Next step: search apartment B."


Context Compaction is that detective's notebook: When our prompt grows past 6,000 tokens, Agent.compact_context() prompts the LLM to summarize all older commands, failed hypotheses, and file edits into structured working memory, while keeping the original instructions and the most recent tool step verbatim.

Before Compaction (Bloated)

[System Prompt] • 800 tokens
[Task Prompt] • 200 tokens
[Step 1 Action + 500-line pytest dump] • 3,200 tokens
[Step 2 Action + 300-line git diff] • 2,100 tokens
[Step 3 Action + file inspect] • 1,900 tokens
------------------------------------
Total Active Context: 8,200 Tokens (Exceeded Threshold!)

After Compaction (Compact)

[System Prompt] • 800 tokens (VERBATIM)
[Task Prompt] • 200 tokens (VERBATIM)
[Working Memory Summary] • 250 tokens (FACTS ONLY)
[Step 3 Action + file inspect] • 1,900 tokens (RECENT STEP)
------------------------------------
Total Active Context: 3,150 Tokens (61% Reduction!)

♟ Domain Specialization

The ChessAgent & Programmatic Tool Calling

Empowering models to plan via code execution rather than token hallucination.

❌ Naive Agent: Mental Lookahead

An LLM playing chess from prompt text must hallucinate piece coordinates in its attention heads. It cannot look ahead 3 plies without making illegal moves, getting pieces pinned, or losing its queen.

✅ Programmatic Tool: Search via Code

With run_python, the agent writes a Python script containing a minimax search or heuristic loop. The script executes inside the sandbox beside the chess server, calling simulate_move() in a loop.

How Programmatic Tool Calling Executes (sandbox_python.py) 
# 1. Model outputs Python code in run_python tool argument:
code = """
best_move = None
best_score = -999
for m in ["e2e4", "d2d4", "g1f3"]:
    state = simulate_move(fen, m)
    score = len(state['legal_moves']) + (10 if state['in_check'] else 0)
    if score > best_score:
        best_score = score
        best_move = m
play_move(best_move)
"""

# 2. Local agent base64 encodes the code string (preventing shell quote escapes):
encoded = base64.b64encode(code.encode()).decode()

# 3. Executes on remote Modal sandbox:
env.execute(f"python /opt/assignment/sandbox_python.py 8000 {encoded}")

# 4. sandbox_python.py executes the code with simulate_move/play_move bound to localhost:8000!
